## Design Context

### Users

Developers and open-source maintainers who want to turn a conventional GitHub README into a memorable, highly designed document without losing the familiarity of Markdown authoring.

### Brand Personality

Editorial, ambitious, technically credible. The product should make authors feel that their project has received the same visual care as the software itself.

### Aesthetic Direction

Dark technical-editorial presentation with exact GitHub light and dark page surfaces. The work should be striking at first glance but retain the proportions, rhythm, and information density of a serious README rather than becoming a generic marketing landing page.

### Design Principles

- Make authored Markdown feel unexpectedly premium while preserving its structure.
- Use opt-in raw HTML primitives for exceptional layouts; never infer author intent.
- Maintain light and dark parity so exports blend naturally into GitHub.
- Favor sharp hierarchy, purposeful framing, and dense useful detail over decorative noise.
- Keep the rendering path reproducible: one source document, one shared renderer, deterministic assets.
